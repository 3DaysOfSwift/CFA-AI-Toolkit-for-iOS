# Runnable CFA examples

## Notes reference feature

[NotesReference.swift](NotesReference.swift) demonstrates a screen View, its ViewModel, a Feature, JSON persistence and AppModel composition. Each save submits one new note. The file-backed repository reads the current collection and atomically rewrites it in one actor turn. This keeps overlapping saves through that repository from replacing each other with stale copies. [NotesReferenceTests.swift](NotesReferenceTests.swift) exercises load and save failure recovery, publication after persistence, repeated Save taps, ordered independent saves, JSON persistence and fresh editor state. A queued save still completes when its predecessor fails, and each caller receives its own outcome. Two callers share one load even if one cancels. Saving during restoration preserves both restored and newly saved notes. The checks verify that a failed save preserves a corrupt file and that retrying after file recovery restores saved notes and retains the draft. From this directory on macOS with Xcode and Swift 6, run:

`xcrun swiftc -swift-version 6 -parse-as-library NotesReference.swift NotesReferenceTests.swift -o /tmp/cfa-notes-tests && /tmp/cfa-notes-tests`

This is a composable feature slice, not a complete app or a SwiftUI navigation test. See [starter apps and open-source projects](open-source-apps.md) for complete projects.

## Deep-linking example

Run on macOS 14 or later with Swift 6 language mode:

`swiftc -swift-version 6 -parse-as-library DeepLinkingExample.swift -o /tmp/cfa-deep-link-example && /tmp/cfa-deep-link-example`

The example rejects blank event or destination identifiers before saving and verifies that the previously saved requests survive reopening the store. It then simulates a scene declining navigation, restores the request in a new Feature instance, and removes it after simulated navigation. It checks repeated callbacks for the same opening request, competing scene attempts, independent scene destinations, cancellation before and after navigation, an initial save failure that leaves the pending list unchanged, and a failed removal after navigation. It also verifies that receiving a request before or during restoration preserves all pending items across restart, and dismissing one request preserves the others. Expected output begins with “Passed”. The Feature accesses persistence through PendingRequestRepository. The app supplies the typed destination request after interpreting its URL or notification payload and provides the scene navigation handler. The file store and handler are deliberately small teaching implementations: this is not a notification delegate, URL parser, multi-process store, or a real SwiftUI navigation flow. Competing opens or dismissals of the same active request return an operation-in-progress error to their callers. If navigation succeeds and durable removal fails, the example reports the failure and retries removal without navigating again in the current process. If the process exits before removal succeeds, the stored request can reappear on restart. The request ID identifies one opening event. Repeated callbacks for that event reuse its ID. A new opening request gets a new ID even if it points to the same destination. The example keeps resolved IDs in memory for the store’s lifetime. Real applications must handle expiration, duplicate opening callbacks across restarts and scene lifetimes according to the specification.
