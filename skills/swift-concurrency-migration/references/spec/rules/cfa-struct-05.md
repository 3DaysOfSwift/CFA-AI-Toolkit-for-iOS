# CFA-SPEC-STRUCT-05: Apply optional visual defaults only in scope

**Applies when:** Shaping a new app or changing an existing product.

**Strength:** Default with scope restriction.

**Guidance:** Use new-product visual defaults when applicable and preserve existing approved designs during maintenance.

**Why:** An architecture task should not silently redesign an existing product.

**Example:** Do not add a CFA Settings footer to an established app unless the request or workflow calls for it.

**Explanation:** [Why use opt-in design defaults in our code?](https://www.3daysofswiftconcurrency.com/cfa/explanation/new-app-design).

**Verify:** Compare UI changes with user instructions and the product design authority.
