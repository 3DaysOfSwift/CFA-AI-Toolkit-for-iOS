# Changelog

## 0.3.2 — 2026-10-29

- Define Features as main-actor owners of authoritative application state for
  business capabilities. Distinguish that ownership from service-internal caches,
  request tracking and storage machinery.
- Replace mandatory Feature-per-tab ownership with capability-based boundaries.
  Screens may combine several Features; growing ViewModels extract business
  behaviour only when it represents a model responsibility.
- Bundle a shared explanation catalogue, 17 design-decision notes and local
  lookup/validation tools with all eight skills. Separate confirmed rationale
  from editorial analysis; never offer unverified article URLs as published links.
- Separate runnable Starter Apps from installable Xcode templates and exclude
  local Xcode state/build output from release archives.
- Strengthen screen construction checks, app identity/orientation verification,
  migration completion evidence and the corresponding workflow guidance.
- Preserve product behaviour during adoption. Existing composed Features are
  reviewed as explicit architectural extensions, not mechanically split or removed.

## 0.3.1 — 2026-10-25

- Add opt-in migration evidence capture: a versioned scenario schema, case-study
  template, synthetic example and dependency-free local validation helper.
- Record behaviour contracts, decisions, alternatives, human corrections and
  verification, separating general Swift Concurrency guidance from CFA choices.
- Add review fingerprints and publication-eligibility checks; exclude drafts,
  synthetic examples, holdouts and records without redistribution/privacy clearance.
  Keep working records outside application repositories and release payloads.
- Bundle capture tools with the migration skill for portable installation. This
  is capture infrastructure, not automatic retrieval or a real migration corpus.
- Add Habit Tracker and Day Streak native Xcode templates and a separate Habit
  Tracker Pro project demonstrating Swift Charts and a StoreKit Trends unlock.
- Strengthen Settings, feature-per-tab, test ownership, AppModel composition,
  lifecycle and feature-owned persistence guidance. Improve template naming,
  task ownership, inline editing and first-use storage behaviour.

- Separate new-app visual defaults from CFA architecture requirements.
- Extend App Creation through ongoing new-product development and record the
  project workflow without repeatedly asking or resetting approved designs.
- Preserve existing-product UI during feature work, adoption, migration and
  tidy-up; remove recurring theme offers and automatic starter branding.
- Bundle the shared workflow policy with all eight skills, validate delivery,
  and document ten scope-regression scenarios for agent evaluation.

## 0.3.0 — 2026-10-20

- Deliver eight independent AI skills, the `cfa` command with inspector,
  dashboard, doctor, and project-guidance commands, and the native CFA App
  Xcode project template in both release archives.
- Adopt **CFA AI Toolkit for iOS** as the public display brand while keeping
  the installed plugin identifier and repository URL stable.
- Name concrete feature owners `*Feature` and match their AppModel properties,
  ViewModel dependencies, and local references. Align the Xcode template,
  bundled skills, project guidance, and inspector vocabulary; existing apps
  are not automatically renamed.
- Add CFA Codebase Tidy, CFA Feature Work, CFA Unit Tests, and Swift Code
  Quality workflows. Expand the installer and local architecture review tools.
- Add practical installation guidance and links to related Swift Concurrency
  articles in the README.
